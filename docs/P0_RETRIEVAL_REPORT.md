# P0 检索实验报告：世界书触发通道验证

> 日期：2026-09-13 · 环境：Windows / Python 3.8.6 · 全部零依赖纯 Python，可复跑
> 复跑方式：`python build_corpus.py && python run_eval.py`
> 实验包：`p0-retrieval-exp/`（build_corpus.py / retrieval.py / annotations.json / run_eval.py / results.json）

## 1. 实验目的

回答开发计划 P0 的核心问题：**瘦上下文的"世界书按需检索"在真实卡上能不能立住？**
具体验证三件事：
1. 酒馆式字面触发（keys 命中）在中文改写查询下的失效程度；
2. 零依赖的词法通道（字符 bigram BM25）能兜住多少；
3. 常驻条目排除在检索候选之外、始终注入的设计是否正确。

## 2. 语料与查询

- **语料**：仓库 11 张已蒸馏卡的世界书 → 条目级统一 JSON，共 **148 条目**（常驻 58 / 非常驻 90）。
  三种真实画像全部出现：
  - 纯触发词条目（八等分 16 条、兽血 10 条、大秦 23 条——其中 16 条连条目名都没有，原卡 comment 为空）；
  - 纯常驻无触发（出云国 15 条、色色任务系统 12 条——对它们"检索"无意义，永远注入）；
  - 无触发词的大段散文（清漪映雪 22 条，标题是内容内部标题，靠词法/语义才能命中）。
- **查询**：43 条人工标注（19 条字面命中型 + 23 条中文改写型 + 1 条常驻覆盖型），
  模拟玩家真实发言（"西北的蛮子今年又南下抢粮了" → 应命中【边境威胁】条目）。
  改写型查询刻意避开了所有触发词。

## 3. 结果

| 通道 | 总体 R@5 | 总体 MRR | 字面型 R@5 | 改写型 R@5 |
|---|---|---|---|---|
| key（酒馆式触发，baseline） | 0.500 | 0.500 | **1.000** | **0.087** |
| lex（字符 bigram BM25，零依赖） | 0.905 | 0.820 | 1.000 | 0.826 |
| hybrid（key+lex RRF 融合） | **0.905** | **0.850** | 1.000 | 0.826 |

- 常驻覆盖型查询（所需信息在常驻条目中，期望检索返回空）在所有通道 100% 正确——
  **"常驻=始终注入、不参与检索"的设计得到验证**。
- 分卡看 hybrid：五张卡 R@5=1.000（八等分/兽血/凌夜/大夏/清漪），唯一下拉项是
  大秦纵横 R@5=0.667（它的条目多、机构术语密度高）。
- 单条查询检索耗时毫秒级（43×3 全量评测 4ms），148 条目规模下无性能顾虑。

## 4. 关键发现

1. **酒馆式字面触发的改写失效率被定量证实**：改写型查询 R@5 只有 **8.7%**——
   "官方术语→日常用语"的翻译断裂是结构性的，不是调参能救的。这就是"玩家说人话，世界书装死"的量化版本。
2. **词法兜底通道收益巨大**：仅用字符 bigram BM25（没有分词、没有向量、没有任何中文 NLP 依赖），
   改写型召回就从 8.7% 拉到 82.6%。因为条目正文里通常**复述了同一概念的白话版本**，
   bigram 的模糊匹配恰好能搭上桥。
3. **hybrid 是正确的融合方式**：key 通道保证字面查询的精确率与排名（MRR 1.000），
   lex 通道补改写召回，RRF 融合后两头都占。
4. **剩余 4 个失败案例全部是纯同义词替换**，且集中在大秦纵横：
   蛮子→蛮夷/异族、税→赋税、级别→品级、部队→军队——查询与条目**零字符重叠**。
   这正是 embedding 通道的教科书场景，证明词法通道到顶之后**向量通道仍是必需的**，
   与"bge-m3 本地跑 + API 兜底"的计划判断一致。
5. **语料画像直接转化为运行时设计约束**：
   - 无名条目（comment 为空）只能靠 keys+正文检索 → 标题必须回退生成；
   - 全常驻卡（出云国等）检索层为空是**正常状态**，运行时不得报错；
   - 清漪映雪式散文卡没有 keys，检索唯一抓手是正文 → 字段权重里正文权重不能太低。

## 5. 对开发计划的决策输入

| 计划项 | 实验结论 |
|---|---|
| P2 检索选型 | **key + lex 双通道为必选基线，embedding 为第三通道**；hybrid RRF 融合策略成立 |
| P0 验收（recall@5 ≥ 90%） | 词法通道已达标（0.905），embedding 上线后预期覆盖剩余同义词缺口 |
| 评测集 | 43 条标注 v1 可用，作为回归基线；P1 扩到 11 卡全量 + 真实会话查询 |
| 工程依赖 | 检索核心可零依赖实现（本次已验证）；jieba/tantivy 是优化项而非前置项 |

## 6. 局限（如实声明）

1. **标注由本项目作者（LLM）生成**，可能存在向自家分词器倾斜的偏差；上线前需真人标注校准。
2. 43 条查询规模仅为管道验证级，未覆盖多轮上下文查询（"她刚才说的那个地方"）和跨条目组合查询。
3. lex 通道是**向量通道的代理**，不是它的下界或上界——bge-m3 的真实增益需在能下载模型的环境补测。
4. 查询是孤立句，未带对话历史；真实会话中代词消解会改变召回分布。
